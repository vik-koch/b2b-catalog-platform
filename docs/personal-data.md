# The personal data the platform holds

Every kind of personal data the platform holds: whose it is, where it is kept, what
it is held for, how long it lives, how it ends, and who outside the platform receives
it ([NFR-LEGAL-13](requirements.md#nfr-legal-13)). A shop writes its privacy policy
from this page, along with whatever its jurisdiction asks a controller to file or
keep about its processing. The platform writes neither, and nothing here is legal
advice.

What follows is the platform **as it currently stands**. It names kinds of recipient,
never providers. Every point a deployment decides is marked **⚙** with the setting
that decides it, so a deployment completes this page with its own providers and
values instead of rewriting it. Figures given without a ⚙ are fixed in code.

**It has to be kept current.** A change that adds a kind of personal data, a place it
is copied to or a recipient updates this page in the same change.

## Whose data

| Who                          | How they reach the platform                                                                                                                                                                                                   |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Account holders**          | They register ([FR-AUTH-01](requirements.md#fr-auth-01)), are invited by staff ([FR-AUTH-04](requirements.md#fr-auth-04)), or are created by an external system that owns customers ([FR-ADM-11](requirements.md#fr-adm-11)). |
| **Guests**                   | They order without an account ([FR-CART-03](requirements.md#fr-cart-03)).                                                                                                                                                     |
| **People named on an order** | A colleague given as the contact, or another party the order is invoiced to ([FR-CART-09](requirements.md#fr-cart-09)). The customer typed their details, so the platform never hears from them directly.                     |
| **People who write in**      | They send the contact form ([FR-NAV-06](requirements.md#fr-nav-06)).                                                                                                                                                          |
| **Staff**                    | Admins and managers. The platform's trails record who did what.                                                                                                                                                               |
| **Visitors**                 | Anyone browsing. The platform keeps nothing about them on the server. What their own browser keeps is listed under [In the visitor's browser](#in-the-visitors-browser).                                                      |

## In the database

| Data                                                                                                                                                                                                                                                                                               | Whose                                                               | Held for                                                                                                                                                                         | Lives until                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **The account:** email address, password hash, first and last name, phone number, whether a person or a company, company name and registration number, price group, role, status, when it was approved and by whom, when it last signed in, and when its phone number was last confirmed by a code | Account holders, staff                                              | Signing in. Assessing a registration. Pricing, invoicing and contacting the customer. The last sign-in is kept so that an account nobody uses can later be ended after a period. | The account is deleted by its holder ([FR-AUTH-06](requirements.md#fr-auth-06)) or by an admin ([FR-ADM-23](requirements.md#fr-adm-23)). The row stays as a tombstone with everything personal cleared and the email replaced. A registration that is declined is removed outright ([FR-AUTH-11](requirements.md#fr-auth-11)). An account that is switched off keeps everything.                                                                                           |
| **The address book:** street, postal code, city, region, country, an optional label                                                                                                                                                                                                                | Account holders                                                     | Delivering and invoicing.                                                                                                                                                        | Deleted with the account. The holder can delete a single address at any time.                                                                                                                                                                                                                                                                                                                                                                                              |
| **Password links:** the hash of each link, the time it expires and the time it was used                                                                                                                                                                                                            | Account holders, staff                                              | Choosing a password from an invitation or a reset ([FR-AUTH-02](requirements.md#fr-auth-02)).                                                                                    | A link expires seven days after it is sent. The row is kept, so a second click can say "already used". It goes when its account's row is removed.                                                                                                                                                                                                                                                                                                                          |
| **Sign-in codes** ([FR-AUTH-12](requirements.md#fr-auth-12)): the hash of the code an account is waiting on, the phone number it went to, and how often it was sent and tried                                                                                                                      | Account holders, staff                                              | The code after the password, and confirming a number.                                                                                                                            | Removed when the code is used, and with the account's deletion. Otherwise kept until half an hour after the last code was sent, so the limit on codes holds, and removed at the next code anyone is sent.                                                                                                                                                                                                                                                                  |
| **Orders**, in every version: contact name, email and phone; the invoiced party's name and registration number; invoice and delivery address; preferred date; the customer's note; line notes; the manager's note on a version; the price list it was charged from                                 | Account holders, guests, people named on an order                   | Fulfilling the order, and the shop's record of what was agreed ([FR-ORD-03](requirements.md#fr-ord-03)).                                                                         | ⚙ `retention.orderDays` after the order is finished: completed, declined or cancelled, with no payment awaited. The period counts from the last thing that happened to the order ([NFR-LEGAL-14](requirements.md#nfr-legal-14)). The order, its lines and its totals stay, and staff see when its details went. |
| **Documents supplied for an order** ([FR-ORD-05](requirements.md#fr-ord-05)), such as an invoice: files in the private store                                                                                                                                                                       | Account holders, guests                                             | Handing the customer the shop's paperwork.                                                                                                                                       | Removed when they are replaced or taken off the order, and together with the order's personal details.                                                                                                                                                                                                                                                                                                                                                                     |
| **The terms an order accepted, and its tax basis**                                                                                                                                                                                                                                                 | —                                                                   | No personal data of their own: they point at a page version.                                                                                                                     | —                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Consent records** ([NFR-LEGAL-09](requirements.md#nfr-legal-09)): purpose, text version, time, the account's id, and the email address or phone number given                                                                                                                                     | Account holders, people who write in                                | Proving that consent was given, and when it ended.                                                                                                                               | ⚙ `retention.consentRecordDays` after the withdrawal, or after it was given for a contact consent. The record keeps the address after the account is deleted.                                                                                                                                                                                                                                                                                                              |
| **Destruction records** ([NFR-LEGAL-12](requirements.md#nfr-legal-12)): the id of whose data it was, the categories, the reason, who did it, and when                                                                                                                                              | Account holders, people who write in, staff (as the one who did it) | Proving a destruction.                                                                                                                                                           | ⚙ `retention.destructionRecordDays`.                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Customer sync runs** ([FR-ADM-11](requirements.md#fr-adm-11)/[12](requirements.md#fr-adm-12)): what a run carried and what it changed, including names, addresses and contact details                                                                                                            | Account holders                                                     | Reviewing and applying a run.                                                                                                                                                    | The carried and changed rows are dropped a day after the run. The run and its counts stay.                                                                                                                                                                                                                                                                                                                                                                                 |
| **Staff trails:** the staff member's id, and their email address copied in beside it, on page versions, sync runs, machine credentials, setting changes, consent withdrawals and destruction records. The same id appears on catalog edits and order versions.                                     | Staff                                                               | Accountability: who changed a text, who ran an import, who issued a credential.                                                                                                  | As long as the record they are part of. A copied address **stays when the staff account is deleted**, because a trail that names nobody proves nothing.                                                                                                                                                                                                                                                                                                                    |

**Inquiries** are not stored. A contact-form message (name, email, phone, the
preferred way to reply, and the text) is mailed to the shop and kept nowhere else.
The only thing stored is the consent record, where the deployment asks for one.

**Order summaries** are generated when someone opens or downloads one, and are not
stored. The same goes for the terms attached to an order confirmation.

## Outside the database

| Where                                     | What                                                                                                                                                                                                                | Lives until                                                                                                                                                                                                                                                              |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Application logs** (central log store)  | Email addresses: the recipient of each mail sent, and the staff member or account holder named in an audit line. Ids and order references. Not message bodies, and not what a person types into a suggestion field. | 14 days, then removed by the log store's retention. Deleting a person does not reach them.                                                                                                                                                                               |
| **Proxy access logs** (central log store) | Host, method, path, status and duration. **Not the client's IP address**, and no headers or cookies. The credential in a mailed link's path is replaced before storage.                                             | 14 days.                                                                                                                                                                                                                                                                 |
| **Container logs on the host**            | The same lines, before they reach the store. The proxy's copy still carries the credential in a mailed link's path.                                                                                                 | Rotated by size (3 × 10 MB per container, 2 × 10 MB for the proxy), so they usually last days.                                                                                                                                                                           |
| **Database backups**                      | The whole database.                                                                                                                                                                                                 | ⚙ `BACKUP_KEEP_DAYS` / `_WEEKS` / `_MONTHS`: 14 daily, 8 weekly and 6 monthly copies by default, **so a deleted person survives in a backup for up to six months**. A restore brings them back, so a deletion made after a backup has to be repeated after restoring it. |
| **File backups**                          | The file store, including documents supplied for orders.                                                                                                                                                            | ⚙ `BACKUP_KEEP_DAYS`, 14 days by default.                                                                                                                                                                                                                                |
| **Off-site copies**                       | Whatever the operator pulls from the server with `infra/backup.sh`.                                                                                                                                                 | ⚙ The operator's own copies, on the operator's own machine. The platform does not manage them.                                                                                                                                                                           |
| **The mail queue**                        | A mail waiting to be sent.                                                                                                                                                                                          | In memory only, until sent. Lost on a restart.                                                                                                                                                                                                                           |
| **Rate limiting**                         | The client's IP address, as a counter.                                                                                                                                                                              | In memory only, for the length of the limit's window. Never written down.                                                                                                                                                                                                |

## In the visitor's browser

| Name                                   | Kind             | What                                                                             | Lives until                                       |
| -------------------------------------- | ---------------- | -------------------------------------------------------------------------------- | ------------------------------------------------- |
| `session`                              | Cookie, httpOnly | A signed token naming the account.                                               | 7 days, or signing out.                           |
| `session_role`                         | Cookie           | The role only, so the first frame renders the right controls.                    | Like the session.                                 |
| `sign_in_step`                         | Cookie, httpOnly | A signed token naming the account between the password and the code.             | 15 minutes, or the code being entered.            |
| `product_layout`                       | Cookie           | Cards or lines.                                                                  | One year.                                         |
| `cart`                                 | Local storage    | The cart's lines, including line notes, which a customer can fill with anything. | Until the order is placed or the cart is emptied. |
| `checkout-draft`                       | Session storage  | Checkout answers so far, including contact details, addresses and the note.      | Closing the tab, or placing the order.            |
| `cookie-consent`                       | Local storage    | The visitor's cookie choice.                                                     | Until the visitor clears it.                      |
| `last-listing`                         | Session storage  | The last catalog page, for the back link.                                        | Closing the tab.                                  |
| `admin-edit-mode`, `admin_grid_widths` | Local storage    | Staff display preferences.                                                       | Until cleared.                                    |

None of these goes to a third party. A third party's cookies appear only once an
embedded map loads, as described below.

## Who outside the platform receives it

| Recipient                                                              | What                                                                                                                                                                                             | When                                                                                                                                                                                                                                | Decided by                                                                                                                                                              |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **The hosting provider**                                               | Everything above that lives on the server or its backups.                                                                                                                                        | Always.                                                                                                                                                                                                                             | ⚙ The deployment's choice of host and region ([NFR-LEGAL-05](requirements.md#nfr-legal-05)).                                                                            |
| **The mail provider**                                                  | Every mail: to customers, to the shop's own addresses, and every contact-form message. They carry names, addresses, order contents and contact details.                                          | Every mail sent.                                                                                                                                                                                                                    | ⚙ `MAIL_HOST` and the rest of the `MAIL_*` settings. The shop's own inbox (`MAIL_STAFF_TO`, `MAIL_ADMIN_TO`) is the shop's system, and nothing deleted here reaches it. |
| **An external system that owns or reads customers or orders** (an ERP) | Account details and orders, read outward ([FR-ADM-08](requirements.md#fr-adm-08), [FR-ADM-18](requirements.md#fr-adm-18)). Account details sent inward ([FR-ADM-11](requirements.md#fr-adm-11)). | Only once a machine credential carrying the matching scope is issued ([NFR-LEGAL-07](requirements.md#nfr-legal-07)).                                                                                                                | ⚙ An admin issuing the credential. A deleted account is reported as withdrawn, and that system keeps its own record ([NFR-LEGAL-08](requirements.md#nfr-legal-08)).     |
| **The suggestion provider**                                            | What a person types into a company or address field at registration or checkout, passed on by the deployment's sidecar.                                                                          | While they type, if the deployment runs a sidecar. Nothing is stored or logged here.                                                                                                                                                | ⚙ `SUGGESTION_SIDECAR_URL`. The provider behind the sidecar is the deployment's.                                                                                        |
| **The code provider**                                                  | The account's phone number and the message carrying the code, passed on by the deployment's sidecar.                                                                                             | Each time a code is sent ([FR-AUTH-12](requirements.md#fr-auth-12)).                                                                                                                                                                | ⚙ `signInStep` in `deployment.json`, and `SIGN_IN_CODE_URL`. Without the URL, codes go by mail, to the mail provider.                                                   |
| **The map provider**                                                   | The visitor's IP address and whatever the provider's own embed collects.                                                                                                                         | Once the contact page's map loads. Where the embed is marked `consentRequired`, only after the visitor allows it, from the cookie banner or the map's own button ([NFR-LEGAL-03](requirements.md#nfr-legal-03)). The demo marks it. | ⚙ The map's embed URL and its `consentRequired` flag in `deployment.json`.                                                                                              |

The web app loads nothing else from another host: fonts, scripts and images are all
served by the platform itself.

## What a deployment decides

| Setting                                                                     | Decides                                                                                                                                                                                      |
| --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `consent.contact`, `consent.account`                                        | Whether consent is asked for and recorded at all ([NFR-LEGAL-09](requirements.md#nfr-legal-09)). Where it is off, the processing rests on another ground, and the privacy policy says which. |
| `retention.orderDays`                                                       | How long a finished order keeps its personal details.                                                                                                                                        |
| `retention.consentRecordDays`, `retention.destructionRecordDays`            | How long consent and destruction records outlive what they record.                                                                                                                           |
| `cookieConsentEnabled`, the map's `consentRequired`                         | Whether non-essential cookies wait for a choice.                                                                                                                                             |
| `BACKUP_KEEP_DAYS`, `BACKUP_KEEP_WEEKS`, `BACKUP_KEEP_MONTHS`               | How long a deleted person survives in backups.                                                                                                                                               |
| `MAIL_*`, `SUGGESTION_SIDECAR_URL`, `SIGN_IN_CODE_URL`, the map's embed URL | Which providers receive data.                                                                                                                                                                |
| The machine credentials an admin issues                                     | Whether an external system receives account details and orders.                                                                                                                              |
| The host                                                                    | Where everything is stored, and under which jurisdiction.                                                                                                                                    |

## When deleting a person takes effect

Deleting an account clears it from the database at once, together with its addresses,
the personal details on its orders and the documents supplied for them, and writes a
destruction record. A guest has no account: an admin removes the details from each of
their finished orders on request, finding them in the order list by email address. The
copies outside the database follow on their own schedules:

| Copy                                                             | Gone after                                                 |
| ---------------------------------------------------------------- | ---------------------------------------------------------- |
| The database, and the supplied documents in the file store       | Immediately.                                               |
| Application and proxy logs                                       | 14 days at most.                                           |
| Container logs on the host                                       | The next rotations.                                        |
| File backups                                                     | ⚙ 14 days by default.                                      |
| Database backups                                                 | ⚙ Six months by default.                                   |
| The consent record                                               | ⚙ `retention.consentRecordDays` after the deletion.        |
| Mail already sent, the shop's inbox, an external system's record | Never by the platform. Each is the receiving system's own. |
